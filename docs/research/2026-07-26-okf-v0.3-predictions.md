# Predictions: OKF v0.3

Dated 2026-07-26, two days after v0.2 shipped. Each prediction is
falsifiable and scored when v0.3 lands (or at the review date, whichever
comes first). Method note: the v0.2 scorecard
(`2026-07-22-okf-type-vocabulary-position.md`) showed our misses come
from paths we didn't enumerate, not from picking the wrong enumerated
branch — so this set includes explicit "what would surprise us" markers.

## Evidence base

1. v0.2 §12 "Considered and deferred" names its own backlog: the
   attestation runtime protocol (receipt/verdict wire formats), the
   attester ABI and sandboxing ("likely bundled with future work on
   serving and Skills"), attestation caching, and semantic-layer
   templates (Looker, dbt).
2. v0.2 §5.1 explicitly scopes out deeper lineage: "an explicit external
   `derived_from`, or data lineage) is out of scope for v0.2."
3. v0.2 blessed one type value with contract fields
   (`Attested Computation`) — a per-type registry path no one predicted.
4. Cadence: v0.1 published 2026-06-12, v0.2 on 2026-07-24 — six weeks.
5. PR-queue triage, 2026-07-26 (two days post-v0.2): **the migration PR
   (#227, internally authored) merged nothing from the community queue.**
   Every watch-list PR is still open. v0.2 absorbed the queue's themes
   (trust, staleness) without its patches. Implications: (a) release
   content is set by the internal roadmap, not queue-draining, so the
   queue predicts v0.3's *pressure*, not its *contents*; (b) some open
   PRs are now zombies — #165 (recommend file-relative links) proposes
   the opposite of what v0.2 §6.1 shipped; #187 (timestamp staleness) is
   superseded by `generated.at`/`stale_after`.
6. Still-live queue pressure: typed relationship edges (#195),
   agent-routing hints (#189), reliability axis (#159), `validate`
   subcommand (#125), okf_version on standalone files (#192).
7. New activity in the runtime-protocol space: #208 adds consumer-receipt
   conformance fixtures (three observed failure cases with an
   `expected.yaml` contract), #205 adds an "organizing-with-okf" Agent
   Skill. The community is building attestation-adjacent material before
   the spec defines it.
8. Bundle-boundary pressure: #232 (opened 2026-07-26) proposes defining
   the conformance corpus — which files a conformance evaluation covers —
   and #190 proposes an `.okfignore` convention. Both target the same gap
   Scriptorium hit with its `raw/` exclusion deviation: v0.2 has no
   concept of a non-concept directory.
9. All four visualizer absolute-link fixes (#66, #110, #184, #206) remain
   unmerged even though v0.2 made bundle-absolute the *recommended* form:
   the reference tooling now silently drops the spec's own recommended
   links. Prediction 3's interop-bug branch is accruing evidence already.

## Predictions

1. **The attestation runtime protocol ships.** v0.3's headline is the
   §12 backlog: receipt/verdict wire formats and/or the attester ABI,
   tied to agent Skills. Confidence: high — a spec that names its own
   deferred work usually does it next, and the community is already
   building receipt fixtures (#208) and OKF Agent Skills (#205) in that
   space. *Refuted if* v0.3 lands without any runtime-protocol content.
2. **A second type value gets spec-blessed contract fields** (the
   one-at-a-time registry continues — a templated computation for
   Looker/dbt, or an executable `Playbook`). Confidence: medium.
   *Refuted if* v0.3 defines no new type contracts.
3. **`type` stays a free string; no vocabulary and no self-description
   convention.** The v0.2 outcome repeats: semantics accrete through
   per-type contracts (prediction 2), not through a registry or a
   glossary mechanism. Confidence: high. *Refuted if* either mechanism
   ships — and if the self-description convention ships, Scriptorium's
   `## Page types` glossary becomes either conformant or stranded within
   one release.
4. **Lineage enters the spec** — a `derived_from` (or equivalent
   explicit external-lineage field), since §5.1 deferred it by name.
   Confidence: medium-low for v0.3 specifically (it competes with the
   runtime protocol for attention); high for "within two minor
   versions." *Refuted for good if* v0.4 ships without it.
5. **Core conformance rules 1–3 survive unchanged again.** Stability of
   the three rules is the spec's real product; both bumps so far kept
   them byte-for-byte. Confidence: high. This is the bet Scriptorium's
   `check_okf` is built on. *Refuted if* v0.3 touches any of the three.
6. **Timing: v0.3 ships between 2026-10-01 and 2026-12-31.** Two-sided
   on purpose. The 0.1→0.2 gap was six weeks, but the queue triage
   (evidence 5) shows releases are internally roadmapped, not
   queue-driven — and the next roadmap item by the spec's own account is
   the runtime protocol, which needs new design coupled to the
   Skills/serving effort rather than writing down decisions already
   made. *Refuted early* if v0.3 lands before October — meaning the
   "protocol is genuinely hard" model is wrong or v0.3 shipped without
   it (check prediction 1). *Refuted late* if nothing ships by year end
   (review 2027-01-01).

7. **A bundle-boundary mechanism enters the spec** — a defined
   conformance corpus, an `.okfignore`, or equivalent text saying which
   files a bundle's conformance evaluation covers. Two independent
   community PRs (#232, #190) target the gap, and it is the kind of
   low-design clarification minor versions absorb. Confidence: medium.
   *Refuted if* v0.3 leaves the boundary undefined. Direct Scriptorium
   upside: our `raw/` exclusion stops being a documented deviation and
   becomes a spec-sanctioned exclusion.

## What would surprise us (unenumerated-path insurance)

- A **major** bump (v1.0) instead of 0.3, freezing the format for an
  enterprise launch.
- Conformance **tooling** shipping ahead of spec text (the #125
  `validate` subcommand becoming the de-facto conformance definition,
  making the reference implementation, not the spec, the thing to track).
- A packaging/serving standard (bundle registry, HTTP serving
  convention) — "how bundles are exchanged" leapfrogging "what bundles
  contain."

## Scriptorium exposure

Prediction 5 is the only one Scriptorium is structurally exposed to on
the downside; a miss there means engine changes. Prediction 7 is the
upside exposure: a spec-defined boundary would legitimize the `raw/`
exclusion (watch #232/#190 for the shape it takes — path convention vs
ignore file matters to `discover_okf_bundle`). Predictions 1–2 are
watch-only (we don't produce computations). Prediction 3's
self-description branch would make our glossary prototype prior art.
Prediction 4 would map cleanly onto `supersedes`-style path fields.
